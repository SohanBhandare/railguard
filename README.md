# RailGuard: Machine Learning-Based Bot Detection for Railway Ticket Booking

RailGuard detects bots on a railway ticket booking website by analysing **how** a
visitor behaves (mouse movement, typing rhythm, clicks, timing) instead of asking
everyone to solve a CAPTCHA. Humans get their ticket, and bots are blocked.

## Features
- Invisible, behaviour-based bot detection
- Two ML algorithms: Random Forest and Isolation Forest, combined with rule-based scoring
- Explainable results: bot probability, risk level and named flags
- Bot simulator to demonstrate detection
- Admin dashboard with charts, IP tracking, IP blocking and model retraining
- SQLite database that stores sessions, features, bookings and events

## Tech stack
Python, Flask, scikit-learn, NumPy, SQLite, HTML, CSS, JavaScript, Chart.js

## How it works
1. The browser records 15 behaviour features while the user fills the booking form.
2. The features are sent to the Flask API (`/api/analyze`).
3. The **Random Forest** gives the probability that the behaviour matches a known bot.
4. The **Isolation Forest** scores how unusual the behaviour is compared with normal humans.
5. Final score = 65% Random Forest + 25% Isolation Forest + 10% rules and IP history.
6. A score of 0.60 or more is treated as a bot and the booking is blocked.

## How to run
```bash
python -m venv venv
venv\Scripts\activate        # Windows (Mac/Linux: source venv/bin/activate)
pip install -r requirements.txt
cd backend
python app.py
```
Then open:
- Booking page: http://127.0.0.1:5000/
- Admin dashboard: http://127.0.0.1:5000/admin

## Demo of the ML models
```bash
cd backend
python demo_ml.py
```
Prints the Random Forest and Isolation Forest scores for a human and for bots.

## Dataset
The model is trained on a **synthetic dataset** generated by the program at first
start-up (2,300 samples: humans and four types of bots). It is saved to
`database/model.pkl`. Sessions stored in the database can be used to retrain the model
(needs at least 20 sessions).

## Limitations
- Trained on synthetic data, so real-world accuracy needs testing on real traffic
- Very human-like bots are hard to detect
- Admin pages have no login, and the IP header can be spoofed (prototype)

## Future scope
- Train on real labelled traffic and report precision, recall and F1-score
- Compare more algorithms and add richer features such as mouse-path shape
- Add admin authentication and a production database
